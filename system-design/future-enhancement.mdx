### AI-1: Dynamic Menu Recommendations

**What It Does:**
Analyzes cart contents, time of day, and customer history to suggest relevant items.

**How It Works:**

```
Customer adds Coffee to cart
    ↓
AI analyzes: "Coffee + Pastry" bought together 73% of time
    ↓
AI suggests: "Add a croissant for RM 8.90? → Save 15% with combo!"
    ↓
Customer accepts → Revenue +15%
```

**Where It Appears:**

| App | Location | Suggestion Type |
|-----|----------|-----------------|
| **POS Staff** | After adding item | "Upsell popup" |
| **POS Staff** | OrderQueue sidebar | "Frequently bought together" |
| **Customer App** | Menu item page | "Pairs well with..." |
| **Customer App** | Cart screen | "You might also like..." |
| **Customer App** | Order confirmation | "Next time, try..." |

**Business Impact:**
- Average order value ↑ 10-20%
- Customer satisfaction ↑ (relevant suggestions)
- No extra staff effort required

**Implementation Steps:**

```
Step 1: Create recommendation service
├── backend/app/services/recommendation_engine.py
├── get_cart_recommendations(cart_items)
├── get_frequently_bought_together(item_id)
└── get_time_based_recommendations()

Step 2: Create API endpoints
├── POST /api/ai/recommendations
├── GET /api/ai/frequently-bought
└── POST /api/ai/track-recommendation

Step 3: Frontend integration
├── Create AIUpsellPopup.jsx
├── Add to StaffOrder.jsx cart flow
├── Add to OrderQueue.jsx sidebar
└── Add to Customer App menu pages

Step 4: Enable tracking
├── Log when recommendation shown
├── Log when recommendation accepted
└── Calculate conversion rate
```

**Files to Create:**
| File | Purpose |
|------|---------|
| `backend/app/services/recommendation_engine.py` | Core recommendation logic |
| `backend/app/routes/ai_recommendations.py` | API endpoints |
| `frontend/src/components/AIUpsellPopup.jsx` | Upsell popup component |
| `frontend/src/components/AIRecommendationsPanel.jsx` | Sidebar panel |
| `order-app/src/components/MenuRecommendations.jsx` | Customer app recommendations |

**Effort:** 1-2 weeks

### AI-2: AI Conversational Ordering

**How It Works:**

```

    ↓
AI understands intent + modifiers
    ↓
AI: "Sure! I've added Penne Arrabiata (no mushrooms) to your order. 
     Would you like garlic bread as a side? It's a popular choice!"
    ↓
Customer: "Yes, add it"
    ↓
AI: "Great! Anything to drink?"
    ↓
Customer: "One iced lemon tea please"
    ↓
AI: "Perfect! Your order total is RM 45.90. 
     Shall I proceed to payment?"

**Benefits:**

├── Track conversation state
└── Handle multi-turn dialogues

Step 3: Add to Customer App
├── Floating chat button
├── Chat-based ordering interface
└── Order confirmation from chat
```

**Effort:** 2-3 weeks

### AI-4: Demand Forecasting

**What It Does:**
Predicts future sales based on historical data, weather, events, and trends.

**How It Helps:**

```
Tomorrow's Weather: Rainy 🌧️
    ↓
AI Forecast: "Rainy days = 25% increase in delivery orders"
    ↓
Recommendation:
├── 📦 Stock up on delivery packaging
├── 🧑‍🍳 Schedule 1 extra delivery rider
├── 🍲 Popular comfort foods: Nasi Lemak, Mee Goreng
└── 💰 Expected revenue: RM 3,200 (vs RM 2,500 on normal days)
```

**Predictions Available:**
- Hourly sales for today/tomorrow
- Daily sales for the week
- Popular items by time slot
- Staff needed by hour
- Ingredient usage forecast

**Benefits:**
- Reduce food waste (15-25% savings)
- Optimize staff scheduling
- Better inventory ordering
- Prepare for high-demand periods

**Implementation Steps:**

```
Step 1: Historical analysis
├── Build time-series model from order data
├── Identify patterns: time, day, weather, events
├── Calculate baseline forecasts
└── Store forecast data

Step 2: External data integration
├── Weather API integration (free tier available)
├── Calendar event detection (public holidays)
├── School holidays for Malaysia
└── Local events (if available via API)

Step 3: Dashboard widget
├── "AI Forecast" card on Dashboard
├── Show tomorrow's prediction
├── Show confidence level
└── Show recommended actions
```

**Effort:** 1-2 weeks

### AI-6: Kitchen Optimization

**What It Does:**
Routes orders to kitchen stations and predicts cooking times.

**How It Works:**

```
New Order Received:
├── Item A (Grill) → Sent to Grill Station
├── Item B (Fryer) → Sent to Fryer Station  
├── Item C (Salad) → Sent to Cold Station
    ↓
AI Calculation:
├── Estimated cook time: 12 minutes
├── Current queue: 5 orders
├── Expected completion: 4:32 PM
    ↓
Customer receives: "Your order will be ready at 4:32 PM 🦸"
```

**Features:**
| Feature | Description |
|---------|-------------|
| **Station Routing** | Auto-route items to correct stations |
| **Cook Time Prediction** | Real-time ETA for each order |
| **Bottleneck Detection** | Alert when station is overloaded |
| **Course Sequencing** | Fire courses in optimal order |

**Benefits:**
- Faster order completion
- Fewer kitchen errors
- Better customer communication
- Identify slow stations for training

**Implementation Steps:**

```
Step 1: Station assignment
├── Define stations per outlet (Grill, Fryer, Salad, etc.)
├── Link menu items to stations
└── Route items on order creation

Step 2: Time estimation
├── Calculate average cook time per item
├── Factor in current queue length
├── Factor in time of day (rush hour vs slow)
└── Provide real-time updates

Step 3: Kitchen display integration
├── Group orders by station
├── Show estimated completion time
├── Alert when order is delayed
└── Track station performance
```

**Effort:** 2-3 weeks

### AI-7: Fraud & Anomaly Detection

**What It Does:**
Detects suspicious activities that might indicate fraud or errors.

**What It Detects:**

| Anomaly | Pattern | Alert |
|---------|---------|-------|
| **Void Abuse** | More than 3 voids in an hour | "⚠️ High void rate detected at Counter 1" |
| **Discount Abuse** | 50%+ discount on order | "⚠️ Large discount applied - approval needed" |
| **Cash Discrepancy** | Cash vs expected after Z-Read | "⚠️ RM 45 over in cash drawer" |
| **Unusual Hours** | Orders placed at odd hours | "⚠️ Order created at 3 AM by staff: John" |
| **Price Manipulation** | Item priced below cost | "⚠️ Price override detected" |

**Benefits:**
- Reduce shrinkage and theft
- Catch errors before they become losses
- Accountability for staff actions
- Peace of mind for owners

**Implementation Steps:**

```
Step 1: Define anomaly rules
├── Void rate thresholds per hour
├── Discount percentage limits
├── Cash reconciliation tolerance
├── Price override boundaries
└── Unusual time windows

Step 2: Real-time monitoring
├── Log all sensitive actions
├── Check against rules on each action
├── Generate alerts when triggered
└── Store anomaly history

Step 3: Dashboard alerts
├── "AI Alerts" panel on Dashboard
├── Push notification for critical alerts
├── Alert history with resolution tracking
└── Weekly anomaly report
```

**Effort:** 1-2 weeks

### AI-10: Voice Ordering

**What It Does:**
Hands-free order taking via speech recognition.

**How It Works:**

```
Customer taps microphone icon
    ↓
Customer speaks: "One latte, one croissant, and the daily special please"
    ↓
AI converts speech to order
    ↓
AI confirms: "I've added:
             • Latte - RM 12
             • Croissant - RM 8.90
             • Today's Special: Grilled Chicken Salad - RM 18
             
             Total: RM 38.90. Add to order?"
    ↓
Customer: "Yes please"
    ↓
Order created ✓
```

**Benefits:**
- Accessibility (hands-free)
- Faster ordering (speech vs typing)
- Reduced cart abandonment
- Unique selling point

**Implementation Steps:**

```
Step 1: Speech-to-text integration
├── Use Web Speech API (free, browser-native)
├── Or use cloud service (Google, AWS)
├── Handle accents and noise
└── Support English and Malay

Step 2: Order parsing
├── Extract items from speech
├── Handle modifiers (no ice, extra sugar)
├── Confirm with customer
└── Handle corrections

Step 3: Voice response
├── Text-to-speech for confirmation
├── Natural conversation flow
└── Fallback to text if voice fails
```

**Effort:** 1-2 weeks
