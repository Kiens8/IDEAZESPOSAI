## 1. Overview

This document describes the integration of **ABA Payway** as an additional payment method for the IDEAZES POS AI subscription SaaS platform.

### 1.1 Objectives

- Add ABA Payway as a payment option for subscription billing
- Support dynamic (variable) amount charges for subscription renewals and upgrades
- Maintain existing Stripe payment flow without disruption
- Support Cambodian market (KHR currency, ABA account payments)

### 1.2 Key Benefits Over Fixed Schedule Payment

| Approach | Token Flag | Amount | Upgrade Support | Proration |
|----------|------------|--------|-----------------|-----------|
| ~~Fixed Schedule~~ | `CITR_FIX` + `MITR_FIX` | Locked | ❌ Problem | ❌ Complex |
| **Dynamic (Chosen)** | `CITU_FLEX` + `MITU_FLEX` | Variable | ✅ Works seamlessly | ✅ Simple |

## 2. ABA Payway Token System

### 2.1 Token Types

| Token Flag | Full Name | Direction | Amount Type | Purpose |
|------------|-----------|-----------|-------------|---------|
| `CITU_FLEX` | Customer-Initiated Unscheduled | Registration | **Dynamic** | Link customer's payment method |
| `MITU_FLEX` | Merchant-Initiated Unscheduled | Auto-charge | **Dynamic** | Charge customer any amount |

### 2.2 Why Dynamic Tokens

- **No fixed amount restriction** — charge any amount per cycle
- **Upgrades work naturally** — $20 → $50 without re-registration
- **Proration simple** — just charge the calculated difference
- **Same token for life** — no need to re-link payment method

## 3. Payment Flow

### 3.1 Subscription Registration (One-time)

```
Customer selects plan + ABA Payway
        ↓
Backend calls ABA Purchase API with CITU_FLEX
        ↓
ABA returns checkout page (modal/redirect)
        ↓
Customer completes payment on ABA
        ↓
ABA sends token callback to our webhook
        ↓
We store ctid + pwt in database
        ↓
Subscription activated
```

### 3.2 Renewal (Recurring)

```
Cron job runs (daily)
        ↓
Find subscriptions due for renewal
        ↓
Call ABA Payment API with MITU_FLEX
        ↓
ABA processes charge from stored token
        ↓
ABA sends webhook confirmation
        ↓
Subscription period extended
```

### 3.3 Upgrade

```
Customer upgrades plan mid-cycle
        ↓
Calculate proration (same as Stripe)
        ↓
Charge prorated difference (MITU_FLEX)
        ↓
Update subscription to new plan
        ↓
Future renewals charge new plan price
```

### 3.4 Cancellation

```
Customer cancels subscription
        ↓
Mark subscription as cancelled
        ↓
Token remains active ( customer's choice to remove via ABA app)
        ↓
No future MITU_FLEX charges
```

## 4. Database Schema

### 4.1 New Table: `aba_payment_tokens`

```python
class ABAPaymentToken(Base):
    __tablename__ = "aba_payment_tokens"
    
    id = Column(Integer, primary_key=True)
    customer_id = Column(Integer, ForeignKey("website_customers.id"), nullable=False)
    subscription_id = Column(Integer, ForeignKey("subscriptions.id"), nullable=True)
    
    # ABA Token Data
    ctid = Column(String(100), nullable=False)       # ABA Customer Token ID
    pwt = Column(String(500), nullable=False)       # PayWay Token (encrypted)
    source_of_fund = Column(String(50))            # "ABA ACCOUNT", "VISA", "MC", etc.
    
    # Token Status
    token_status = Column(String(20), default="active")  # active, frozen, expired
    expired_at = Column(DateTime, nullable=True)
    
    # Metadata
    created_at = Column(DateTime, default=datetime.utcnow)
    updated_at = Column(DateTime, default=datetime.utcnow, onupdate=datetime.utcnow)
```

Add new field:

aba_token_id = Column(Integer, ForeignKey("aba_payment_tokens.id"), nullable=True)

### 5.4 Hash Generation

```python
def generate_aba_hash(data: dict, api_key: str) -> str:
    """
    Generate HMAC-SHA512 hash for ABA Payway API
    Hash fields vary by endpoint - see ABA documentation
    """
    # For Purchase API (registration):
    b4hash = (
        req_time + merchant_id + tran_id + amount +
        items + shipping + firstname + lastname + email +
        phone + type + payment_option + return_url + cancel_url +
        continue_success_url + return_deeplink + currency +
        custom_fields + return_params + payout + lifetime +
        additional_params + skip_success_page + token_flag + frequency
    )
    
    # For Payment API (MITU_FLEX):
    b4hash = (
        request_time + merchant_id + tran_id + amount +
        currency + items + ctid + pwt + first_name +
        last_name + email + phone + purchase_type +
        callback_url + custom_fields + return_params +
        payout + token_flag + shipping_fee
    )
    
    hash_value = base64.b64encode(
        hmac.new(
            api_key.encode(),
            b4hash.encode(),
            hashlib.sha512
        ).digest()
    )
    return hash_value.decode()
```

### 6.3 Signature Verification

```python
def verify_aba_signature(request_body: dict, api_key: str) -> bool:
    received_signature = request.headers.get('X-PAYWAY-HMAC-SHA512')
    
    # Sort fields by key (ascending)
    ksorted = sorted(request_body.items())
    b4hash = ''.join(str(v) for _, v in ksorted if not isinstance(v, dict))
    
    expected_signature = base64.b64encode(
        hmac.new(
            api_key.encode(),
            b4hash.encode(),
            hashlib.sha512
        ).digest()
    )
    
    return hmac.compare_digest(expected_signature, received_signature)
```

## 7. Cron Job: Renewal Processor

### 7.1 Schedule

Daily at 00:00 (midnight) or configurable

### 7.2 Logic

```python
def process_aba_renewals():
    """
    Process due subscription renewals via ABA MITU_FLEX
    """
    due_subscriptions = db.query(Subscription).filter(
        Subscription.payment_method == "aba_payway",
        Subscription.status.in_(["active", "trial"]),
        Subscription.current_period_end <= datetime.utcnow() + timedelta(days=1)
    ).all()
    
    for sub in due_subscriptions:
        # Get current plan price
        plan = db.query(SubscriptionPlan).filter(
            SubscriptionPlan.id == sub.plan_id
        ).first()
        
        # Get ABA token
        token = db.query(ABAPaymentToken).filter(
            ABAPaymentToken.id == sub.aba_token_id,
            ABAPaymentToken.token_status == "active"
        ).first()
        
        if not token:
            # Token expired/frozen - mark for manual review
            send_admin_alert(sub, "ABA token inactive")
            continue
        
        # Calculate amount
        amount = plan.price_monthly if sub.billing_cycle == "monthly" else plan.price_annual
        
        # Call ABA MITU_FLEX
        result = call_aba_payment(token, amount, sub.id)
        
        if result.success:
            # Extend subscription
            extend_subscription_period(sub)
            # Create invoice
            create_invoice(sub, amount, "paid", "aba_payway")
        else:
            # Handle failure - retry logic
            handle_renewal_failure(sub, result)
```

## 11. Error Handling

### 11.1 Token Statuses

| ABA Status | Meaning | Action |
|------------|---------|--------|
| `1` (Active) | Token valid | Use for MITU_FLEX |
| `0` (Removed) | Customer unlinked | Mark token inactive, prompt re-link |
| `2` (Frozen) | Temporarily disabled | Retry later, notify customer |

### 11.2 Payment Failures

| Error Code | Meaning | Action |
|------------|---------|--------|
| `98` | Merchant not found | Check API key |
| `29` | Invalid token | Mark token inactive |
| `28` | Invalid PWT | Re-registration required |
| `03` | Invalid amount | Check amount format |

### 11.3 Retry Logic

```python
MAX_RETRIES = 3
RETRY_DELAYS = [1, 3, 7]  # days

def handle_renewal_failure(subscription, result):
    subscription.payment_retry_count = getattr(subscription, 'payment_retry_count', 0) + 1
    
    if subscription.payment_retry_count < MAX_RETRIES:
        # Schedule retry
        delay = RETRY_DELAYS[subscription.payment_retry_count - 1]
        schedule_retry(subscription, delay)
    else:
        # Mark subscription as past_due
        subscription.status = "past_due"
        send_payment_failed_notification(subscription)
```
