## Overview

The Inventory Management module tracks ingredients and raw materials used in menu preparation for each outlet, enabling accurate food cost calculation, low-stock alerts, and automated reorder notifications.

**This module uses the POS Backend API** (`pos_ai.db`) as it operates at the outlet/POS level.

**Per-Outlet Design:** Each outlet manages its own inventory. The `outlet_id` field ensures inventory data is isolated per outlet.

---

## Design Goals

| Goal | Description |
|------|-------------|
| **Accurate Costing** | Calculate actual food cost per menu item from recipe ingredients |
| **Stock Monitoring** | Track ingredient levels and alert when low |
| **Waste Reduction** | Identify shrinkage and waste patterns |
| **Profitability** | Help restaurants understand true gross margins |

## Cost Calculation

### Actual Cost Formula

```
For each menu item with a recipe:

actual_cost = SUM(ingredient.quantity × ingredient.unit_cost)
```

### Example

| Ingredient | Quantity | Unit Cost | Subtotal |
|-----------|----------|-----------|----------|
| Rice | 200g | $0.02/g | $4.00 |
| Chicken | 150g | $0.01/g | $1.50 |
| Oil | 30ml | $0.02/ml | $0.60 |
| Spices | 10g | $0.03/g | $0.30 |
| **Total** | | | **$6.40** |

### Fallback Logic

```
if menu_item.has_recipe AND recipe has ingredients:
    actual_cost = calculated from recipe
else:
    actual_cost = menu_item.estimated_cost  # fallback
```

## Menu Item Integration

### When Inventory is DISABLED
- `actual_cost` = `estimated_cost` (fallback)
- Recipe features hidden
- Stock features hidden

### When Inventory is ENABLED
- `actual_cost` = calculated from recipe
- `estimated_cost` = manual input (for reference/variance)
- Recipe features visible
- Stock features visible

**GET /api/menu-items/{id}** response:

## Stock Management

### Stock Movements

| Type | Description | When Used |
|------|-------------|-----------|
| `purchase` | Stock received | Receiving new inventory |
| `usage` | Stock consumed | Auto-deducted from orders |
| `adjustment` | Manual count correction | Physical count variance |
| `waste` | Spoilage/loss | Damaged/expired items |

### Auto-Deduction Flow

```
1. Customer places order
2. Order includes menu items
3. For each menu item:
   a. Check if has_recipe = true
   b. If yes, deduct ingredients from stock:
      - Record stock_movement (type: usage)
      - ingredients.current_stock -= quantity
4. If ingredient hits min_stock_level → ALERT
```

### Low Stock Alert

When `current_stock <= min_stock_level`:

```json
{
  "alert_type": "low_stock",
  "ingredient": {
    "id": 5,
    "name": "Chicken Breast",
    "current_stock": 2.5,
    "min_stock_level": 5.0,
    "unit": "kg"
  }
}
```

## Considerations

### Performance
- `actual_cost` calculated on-the-fly (not stored)
- Index on `ingredients.outlet_id` for filtering
- Cache cost calculations if menu items > 1000

### Data Integrity
- Prevent ingredient deletion if used in recipes
- Soft delete for ingredients (keep history)
- Transaction for stock movements

### Migration
- Existing `estimated_cost` preserved
- New `actual_cost` calculated when recipe is created
- No data loss
