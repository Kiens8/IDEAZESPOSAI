### 3. Renewal Invoice Generation

**File:** website_api/scripts/send_notifications.py

New function `generate_renewal_invoices` creates new invoice at period end for active subscriptions.

**Handles next_billing_cycle:**
- Checks if `sub.next_billing_cycle` is set (annual → monthly scheduled change)
- Uses `effective_billing_cycle` for calculating invoice amount
- Applies billing cycle change and clears `next_billing_cycle` after invoice created

```python
# Check for scheduled billing cycle change (annual → monthly at renewal)
effective_billing_cycle = sub.billing_cycle
if sub.next_billing_cycle:
    effective_billing_cycle = sub.next_billing_cycle
    print(f"  Applying billing cycle change: {sub.billing_cycle} → {effective_billing_cycle}")

# Create invoice with effective_billing_cycle price
amount = plan.price_monthly if effective_billing_cycle == 'monthly' else plan.price_annual

# ... create invoice ...

# Apply billing cycle change
if sub.next_billing_cycle:
    sub.billing_cycle = sub.next_billing_cycle
    sub.next_billing_cycle = None  # Clear after applying
```

### 9. next_billing_cycle Field (NEW)

**File:** website_api/app/models/models.py

Added `next_billing_cycle` column to subscriptions table:
```python
next_billing_cycle = Column(String(20), nullable=True)  # For annual → monthly scheduled change at renewal
```

**Purpose:** Allows customers to schedule a billing cycle downgrade (annual → monthly) to take effect at renewal.

**Upgrade API Behavior:**
```python
if sub.billing_cycle == 'annual' and upgrade_data.billing_cycle == 'monthly':
    sub.next_billing_cycle = 'monthly'
    # Returns message: "Your billing cycle will change from annual to monthly at your next renewal date..."
```

**Cancel Clears Schedule:**
```python
sub.next_billing_cycle = None  # Clear any scheduled billing change
```

if effective_billing_cycle == 'monthly':

billing_note = ""

### 11. Trial Ending Notices Bug Fix (NEW)

**File:** website_api/scripts/send_notifications.py

Fixed trial ending notices to use `trial_ends_at` instead of `current_period_end`:

```python
# BEFORE (wrong)
customers = db.query(WebsiteCustomer).join(Subscription).filter(
    Subscription.status == 'trial',
    Subscription.current_period_end <= target_date + timedelta(hours=23, minutes=59, seconds=59),
    ...
)

# AFTER (correct)
customers = db.query(WebsiteCustomer).join(Subscription).filter(
    Subscription.status == 'trial',
    Subscription.trial_ends_at != None,
    Subscription.trial_ends_at <= target_date + timedelta(hours=23, minutes=59, seconds=59),
    Subscription.trial_ends_at >= target_date - timedelta(hours=23, minutes=59, seconds=59)
)
```

## Key Flows

### Trial Flow

1. Trial starts with 0 invoice pending
2. Cron marks 0 invoice as paid
3. Trial ends generates first paid invoice
4. Payment converts trial to active

### Free Plan Flow

Same as trial flow - payment method required, 0 invoice generated.

### Cancelled Flow

1. Customer cancels
2. Access continues until period_end
3. After period_end access is blocked
4. Status stays cancelled (not expired)

### Annual → Monthly Scheduled Downgrade (NEW)

1. Customer sets "Switch to monthly at renewal"
2. `next_billing_cycle = "monthly"` stored
3. At renewal, cron applies the change
4. Invoice created with monthly price
