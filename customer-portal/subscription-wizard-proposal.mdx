# Customer Portal Subscription Wizard - Proposal

**Date:** September 23, 2026  
**Status:** Draft - For Review  
**Author:** Lumi

---

## Executive Summary

The current customer portal subscription UI is confusing and not aligned with the new renewal system. This proposal outlines a **step-by-step wizard flow** that guides customers through plan selection, trial/subscription choice, and payment method selection.

---

## Current Issues

1. **Confusing UI** - Multiple states displayed without clear hierarchy
2. **Not aligned with renewal system** - Payment method selection not integrated
3. **Poor user guidance** - Customer doesn't know what to do next
4. **Inconsistent flow** - New vs upgrade customer not differentiated

---

## Proposed Solution: Subscription Wizard

A multi-step wizard that adapts based on:
- Whether customer selected a plan before signup (localStorage)
- Whether customer is new or upgrading
- Plan type (Free, Starter $0, Paid plans)

## Subscription Wizard Steps

### NEW CUSTOMER (Email just verified)

**When:** Customer clicks Subscription menu (new customer, no subscription)

**Display:**
- If `localStorage.selected_plan` exists → Pre-select that plan
- If NOT → Show all available plans as cards

**UI Elements:**
- Plan cards (Free, Starter $99, Pro $199, Enterprise $399)
- Billing cycle toggle (Monthly / Annual)
- Selected plan highlighted
- "Next" button

## Technical Implementation

### Frontend Pages

| Route | Purpose |
|-------|---------|
| `/portal` | Main portal layout with sidebar |
| `/portal/subscription` | Subscription wizard container |
| `/portal/subscription/plan` | Step 1: Plan selection |
| `/portal/subscription/trial` | Step 2: Trial vs Subscribe |
| `/portal/subscription/payment` | Step 3: Payment method |
| `/portal/subscription/confirm` | Confirmation page |

### localStorage Keys

| Key | Description |
|-----|-------------|
| `selected_plan` | Plan ID selected before signup |
| `billing_cycle` | 'monthly' or 'annual' |
| `subscription_choice` | 'trial' or 'subscribe' |
| `payment_method` | 'pay_later' or 'stripe' |
| `wizard_step` | Current step (1, 2, or 3) |

### API Endpoints

| Method | Endpoint | Purpose |
|--------|----------|---------|
| POST | `/api/subscriptions` | Create subscription |
| GET | `/api/subscriptions/current` | Get current subscription |
| PUT | `/api/subscriptions/{id}/trial` | Start trial |
| PUT | `/api/subscriptions/{id}/payment-method` | Update payment method |

### State Management

```
subscriptionState = {
  step: 1 | 2 | 3,
  plan: { id, name, price, billing_cycle },
  choice: 'trial' | 'subscribe',
  paymentMethod: 'pay_later' | 'stripe',
  isEmailVerified: boolean
}
```

## UI/UX Guidelines

### Design Principles

1. **One action per step** - Don't overwhelm customer
2. **Clear progress indicator** - Show which step they're on
3. **Always show summary** - Customer knows what they're getting
4. **Validation before Next** - Can't proceed without selection
5. **Back button always available** - Customer can change mind

### Visual Design

- **Progress bar** at top showing steps (1 → 2 → 3)
- **Selected items** highlighted with blue border + checkmark
- **Disabled buttons** when no selection made
- **Summary sidebar** showing current selections
- **Clean typography** - Arial/Helvetica (matching invoice style)
- **Blue accent color (#1D4ED8)** for buttons and highlights

### Error Handling

| Scenario | Handling |
|----------|----------|
| Email not verified | Show "Verify Email First" message, disable subscription |
| Trial already used | Hide "Start Free Trial" button |
| Payment failed | Show error, allow retry |
| Session expired | Redirect to login |

## Appendix: localStorage Flow

```
Signup Page:
├── User selects plan → localStorage.setItem('selected_plan', planData)
├── User clicks "Get Started" → Redirect to signup
└── After signup → localStorage preserved

OR:

Signup Page:
├── User clicks "Sign Up Free" → No localStorage
└── After signup → localStorage empty

After Email Verification:
├── Click Subscription menu
├── Check localStorage
│   ├── Has plan → Start at Step 2
│   └── No plan → Start at Step 1
└── Wizard proceeds based on steps
```
